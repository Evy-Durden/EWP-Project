\subsection{Discussion}

The chosen technology stack, architecture and personal experience in software development have a profound impact on how the tool will function at the end. Every application has strengths as well as weaknesses and this tool is no exception.

\subsubsection{Strengths}

The tool does not just provide static analysis but also behavioral analysis during runtime. This allows to detect misconfigurations which only appear at runtime. Static scanners only report the file's permissions but eBPF shows whether the dangerous condition is actually exploited. \newline The CLI tool is user-friendly with a minimal learning curve. Even though only a view options are available they can produce a lot of relevant and helpful information.

\subsubsection{Weaknesses and Limitations}

The tool is completely reliant on outside sources for the CVE data.  Consequently this option only works if the system is connected to the internet and the CVE databases can be reached. \newline The tool only provides two types of output at the moment. The output is displayed on the console and optionally it can be put into a text file.

\subsection{Comparison to other Tools}

There are already a plethora of tools on the market which have the same purpose including but not limited to Lynis, LinPEAS and OpenVAS.

\subsubsection{Similarities}

My tool and the exisiting ones implement a static analysis of the system to identify misconfigurations such as weak file permissions, SUID binaries etc.

\subsubsection{Differences}

Some the exisiting tools provide specific and actionable recommendations for system hardening. \newline

My tool also analyzes the system behaviorally during runtime using eBPF.

\subsection{User Feedback}

So far users have concluded that the tool is easy to use and understand. It does provide valuable information however the output on the console could be spaced better and preferably color-coded. It lacking number output formats was also mentioned.
